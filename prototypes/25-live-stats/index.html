Real numbers, fetched.
Shown only when they say something.

A small module fetches GitHub and npm numbers in the browser, keeps them in a two-hour cache, and decides per number whether it's worth showing. Below, the npm button on the mcp-token-optimizer card shows weekly and monthly downloads, and the Code buttons show stars when there are enough. The dotted ring refreshes them.

Notes

  

    
Where it runs
The site is a static export, so the numbers are fetched in the visitor's browser from public endpoints: api.github.com and api.npmjs.org, both open to the browser. No token, no server. GitHub allows 60 calls an hour per visitor without one; the cache keeps a visitor to about one call per repo per two hours.

    
Visits
Repo views and clones come from GitHub's traffic API, which needs a token with push access. That can't go in a public page. It can be done later at build time, in a GitHub Action with a secret, writing the numbers into the build. Stars, forks, watchers, issues and npm downloads need nothing.

    
The cache
A small map of key to value and time, each entry good for the TTL (two hours by default), with calls in flight shared so two buttons asking for the same repo make one request. It's mirrored to this browser's storage, so a reload within the TTL doesn't call again. The ring clears those keys and fetches fresh.

    
Smart showing
A number shows only at or above its threshold, so a new repo never says "1 star". Monthly hides when it equals weekly (the package is under a month old) or falls below the line. If a fetch fails, the button is simply plain: never a zero, a dash or a spinner left behind.
